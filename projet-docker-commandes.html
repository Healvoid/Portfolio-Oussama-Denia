Docker : prise en main des commandes

Mes premières manipulations de Docker en ligne de commande : ce qui marche, ce qui échoue, et pourquoi.

DockerNginxUbuntu WSL 2CLI
Objectif08/06 : commandes10/06 : NginxSuite

Objectif

Après la théorie, j'ai manipulé Docker dans un terminal Ubuntu sous WSL 2 pour me familiariser avec le cycle de vie d'un conteneur : télécharger une image, la lancer, l'inspecter, l'arrêter et la supprimer. Les captures ci-dessous sont mes vraies sessions de travail, erreurs comprises : c'est en les corrigeant qu'on retient les commandes.

Séance du 08/06 : tester les commandes essentielles

CommandeCe qu’elle fait
docker psListe les conteneurs en cours d’exécution : le tableau de bord principal
docker ps -aListe tous les conteneurs (actifs, arrêtés, plantés). Utile pour retrouver l’ID d’un ancien conteneur
docker images / docker image lsListe les images locales et l’espace disque qu’elles occupent
docker run <image>Crée un conteneur à partir d’une image et le démarre immédiatement
docker start <nom_ou_ID>Relance un conteneur existant et arrêté, sans en créer un nouveau
docker stop <nom_ou_ID>Demande un arrêt propre : le conteneur termine ses tâches en cours
docker kill <nom_ou_ID>Arrêt brutal, à réserver aux conteneurs figés
docker logs <nom_ou_ID>Affiche ce que le programme a écrit dans la console : un des premiers réflexes de dépannage
docker exec -it <nom_ou_ID> bashOuvre un terminal dans le conteneur en marche (exit pour sortir)
docker inspect <nom_ou_ID>Métadonnées techniques, par exemple l’adresse IP interne du conteneur
docker rm / docker rmiSupprime un conteneur arrêté / une image
docker system pruneNettoie ce qui ne sert plus (conteneurs arrêtés, réseaux inutilisés...)
docker network lsListe les réseaux Docker

Ce que ces erreurs m'ont appris

  • docker run hello world : le nom d'image est hello-world. Docker a cherché une image hello et a refusé l'accès au dépôt.
  • docker rm 0e a échoué car 0e est l'ID d'une image, pas d'un conteneur : rm supprime les conteneurs, rmi supprime les images.
  • docker stop hello-world a échoué : on désigne un conteneur par son nom ou son ID (ici peaceful_mayer), pas par le nom de l'image.

Séance du 10/06 : images, Nginx et gestion des conteneurs

CommandeCe qu’elle fait
docker pull nginxTélécharge la dernière version de l’image Nginx depuis Docker Hub
docker pull nginx:1.21.0Récupère une version précise grâce à son tag
docker build -t mon_app .Construit une image nommée mon_app à partir du Dockerfile du dossier courant
docker tag / docker pushLie une image à un compte puis la publie sur un registre comme Docker Hub
docker run -d nginxLance Nginx en arrière-plan (mode détaché)
docker run -d --name mon_nginx nginxIdem, avec un nom pour le retrouver facilement
docker exec -it mon_nginx /bin/bashTerminal interactif dans le conteneur
docker restart mon_nginxRedémarre un conteneur sans le recréer
docker rm $(docker ps -a -q)Supprime en une fois tous les conteneurs arrêtés

Erreurs rencontrées

  • Build impossible : failed to read dockerfile: no such file or directory. Il n'y avait pas de Dockerfile dans le dossier courant. Sans Dockerfile, pas d'image mon_app, donc rmi, tag et push échouent à leur tour.
  • Suppression refusée : container is running: stop the container before removing. Il faut arrêter un conteneur avant de le supprimer (ou forcer).
  • Redémarrage impossible : No such container, car j'avais déjà supprimé mon_nginx juste avant.
