Kubernetes : les concepts clés

Comprendre pourquoi et comment Kubernetes orchestre les conteneurs, avant de le manipuler.

Qu'est-ce que Kubernetes ?

Kubernetes (K8s) est un orchestrateur de conteneurs : il répartit les conteneurs sur plusieurs serveurs, les coordonne et les fait fonctionner ensemble pour que l'application ne tombe jamais en panne.

À quoi ça sert

  • Créer des services applicatifs répartis sur plusieurs conteneurs.
  • Planifier leur exécution dans un cluster.
  • Garantir leur intégrité.
  • Assurer le monitoring.

Haute disponibilité : Kubernetes maintient les conteneurs en ligne et lance plusieurs instances selon des paramètres (manuels ou automatiques). Il détecte aussi les pannes et recrée automatiquement les conteneurs défaillants.

Les objets à connaître

ObjetRôle
ServiceIP et port fixes devant les pods : on évite de communiquer directement par IP. Chaîne : Service → IP/port → pods.
VolumeStockage persistant : les données survivent à l’arrêt ou à la suppression d’un conteneur.
Déploiement (Deployment)Objet de gestion des déploiements : création, suppression, mise à l’échelle (scaling) et paramètres de montée ou de réduction de charge.

Du code au cluster

Ordre d'utilisation typique avec Docker :

1. Docker build (créer l'image)→2. Push (stocker dans un registry)→3. kubectl apply (déployer)→4. K8s gère (auto-scale, auto-réparation)

kubectl apply sert à déployer et à gérer les ressources décrites dans un fichier.

Prérequis

  • Les conteneurs (Docker).
  • Le format YAML, format de configuration standard pour Docker Compose, Kubernetes ou les pipelines CI/CD, conçu pour être lisible par un humain.
  • Des bases de réseau (DNS, proxy).
  • Les API REST.

Composants du plan de contrôle

ComposantRôle
kube-apiserverPoint d’entrée unique du cluster. Valide et traite toutes les requêtes (authentification, autorisation, validation).
kube-schedulerLe « planificateur » : assigne les pods aux nœuds selon les ressources disponibles, les contraintes et les affinités.
etcdStockage clé-valeur distribué, source de vérité du cluster : si ce n’est pas dans etcd, ça n’existe pas dans Kubernetes.
kube-controller-managerBoucles de contrôle qui maintiennent l’état désiré (Node Controller, Replication Controller, EndpointSlice Controller).
