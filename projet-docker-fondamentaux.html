Docker : comprendre les conteneurs

Docker, c'est quoi ?

Docker permet de créer, tester et exécuter des applications facilement. Il regroupe le code, les outils et les paramètres dans une unité standardisée : le conteneur. Un conteneur est léger, portable et ne dépend pas de l'ordinateur sur lequel il tourne.

Comment ça marche ?

ÉlémentRôle
Docker EngineCrée et gère les conteneurs. Il se compose du daemon, de l’API et de la CLI (voir ci-dessous).
Daemon (serveur)Programme qui s’exécute en arrière-plan et gère toutes les tâches liées à Docker : création, exécution et distribution des conteneurs.
API DockerEnsemble de règles qui permet aux programmes de communiquer avec le daemon et de lui donner des instructions.
CLIInterface en ligne de commande pour envoyer des ordres au daemon.
Image DockerModèle à partir duquel on crée des conteneurs : il contient le code de l’application et ses dépendances.
DockerfileScript d’instructions qui décrit comment construire une image.
Docker HubRépertoire dans le cloud pour trouver et partager des images.
RegistrySystème de stockage et de distribution des images Docker.
Client (CLI)→ commandes →Daemon→ images →Conteneurs→Applications

Docker s'appuie aussi sur des fonctionnalités du noyau Linux, comme les namespaces, pour isoler les conteneurs les uns des autres et limiter leur accès aux ressources du système. Cette isolation garantit la sécurité et permet à plusieurs conteneurs de tourner sur la même machine sans interférer.

Pourquoi utiliser Docker ?

  • Tout est plus simple, plus rapide et plus fiable : une application et toutes ses dépendances tiennent dans un seul conteneur.
  • Les conteneurs sont légers : on les lance, on les fait évoluer et on les arrête en quelques secondes.
  • Cas d'usage : simplifier les environnements de développement, mettre en place une architecture microservices (application découpée en petits services indépendants pour gagner en évolutivité, en flexibilité et en tolérance aux pannes), l'intégration et le déploiement continus, les applications cloud native et les pratiques DevOps.

Créer un conteneur

1. Obtenir une image

Docker Hub propose de nombreuses images de base prêtes à l'emploi. Pendant le stage, je me suis connecté à un VPS avec un client SSH (PuTTY) pour les manipuler.

sudo docker images          # voir toutes les images du système
docker pull <nom_ou_id>      # télécharger une image

Pour fabriquer sa propre image, on peut passer par un Dockerfile (fichier texte qui indique à Docker comment la construire) ou par Easypanel, un outil qui simplifie la création d'images pour des applications Node.js, Ruby, Python, PHP, Go ou Java.

2. Écrire le Dockerfile, puis créer le conteneur

La mise en pratique complète (Dockerfile, build, run) est détaillée dans le projet Héberger un site dans un conteneur Nginx.

Commandes de gestion vues en stage

CommandeUsage
docker buildConstruire une image à partir d’un Dockerfile
docker runCréer et exécuter un conteneur à partir d’une image
docker run -pMapper les ports entre l’hôte et le conteneur pour joindre l’extérieur (serveur web, base de données...)
sudo docker ps -aLister les conteneurs
docker top MyContainerVoir les processus en cours dans un conteneur
docker statsSuivre la consommation (mémoire, etc.) des conteneurs
docker stop MyContainerArrêter proprement un conteneur
docker kill MyContainerForcer l’arrêt d’un conteneur
