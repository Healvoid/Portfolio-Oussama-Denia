Simulation Red Team vs Blue Team avec CALDERA

Mise en place d'un laboratoire d'attaque-défense avec le framework MITRE CALDERA, pendant mon stage chez Novatiel.

Contexte et objectifs

Ce projet, réalisé pendant mon stage cybersécurité chez Novatiel, consiste à déployer CALDERA, un framework open source développé par le MITRE, pour simuler un affrontement entre une équipe offensive (Red Team) et une équipe défensive (Blue Team) dans un laboratoire isolé.

L'objectif est de comprendre comment fonctionnent les cyberattaques modernes en s'appuyant sur le référentiel MITRE ATT&CK, qui catalogue les tactiques, techniques et procédures (TTP) de véritables groupes d'attaquants.

Objectifs techniques

  • Déployer un serveur CALDERA fonctionnel sur une machine virtuelle Debian.
  • Monter une architecture à plusieurs VM (serveur, attaquant, défenseur) pour simuler un réseau d'entreprise.
  • Répartir quatre rôles : deux attaquants et deux défenseurs.
  • Exécuter une opération offensive automatisée à partir d'un profil d'adversaire ATT&CK.
  • Documenter les résultats et produire des recommandations exploitables.

Installation du serveur

Prérequis système

sudo apt update && sudo apt upgrade -y
sudo apt install -y git python3 python3-pip python3-venv curl wget nodejs npm

Clonage et dépendances Python

git clone https://github.com/mitre/caldera.git --recursive
cd caldera
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

Installation manuelle de Go

L'interface web de CALDERA v5 (plugin Magma) est écrite en Vue.js et nécessite Go pour être compilée. La version fournie par le paquet apt de Debian était trop ancienne (inférieure à 1.19) : j'ai donc installé Go à la main.

wget https://go.dev/dl/go1.21.0.linux-amd64.tar.gz
sudo tar -C /usr/local -xzf go1.21.0.linux-amd64.tar.gz
export PATH=$PATH:/usr/local/go/bin
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc
source ~/.bashrc

Premier lancement, puis lancements suivants

Le build du front-end a pris environ 18 secondes (confirmé par le log VueJS front-end build complete). Ensuite, le flag --build n'est plus nécessaire, sauf si le code de l'interface change.

# Premier lancement (compile l'interface)
source venv/bin/activate
python3 server.py --insecure --build

# Lancements suivants
cd ~/caldera
source venv/bin/activate
python3 server.py --insecure

Comptes par défaut

Lancé avec --insecure, CALDERA crée des comptes de démonstration : admin (accès complet), red (fonctions offensives) et blue (fonctions défensives). C'est acceptable uniquement dans un laboratoire isolé comme celui-ci, jamais sur un réseau exposé.

Déploiement des agents

Un agent est le programme exécuté sur chaque machine cible : c'est lui qui permet à CALDERA d'exécuter des techniques ATT&CK à distance. J'ai utilisé Sandcat (écrit en Go), l'agent par défaut, qui communique en HTTP(S). La commande adaptée à la plateforme et au groupe est générée depuis l'interface (Agents → Deploy an agent).

Agent Red Team

server="http://<IP_SERVEUR>:8888"
curl -s -X POST -H "file:sandcat.go" -H "platform:linux" $server/file/download > splunkd
chmod +x splunkd
./splunkd -server $server -group red -v -name Alex

Agent Blue Team

server="http://<IP_SERVEUR>:8888"
agent=$(curl -svkOJ -X POST -H "file:sandcat.go" -H "platform:linux" -H "group:blue" \
  $server/file/download 2>&1 | grep -oP 'filename="\K[^"]+')
chmod +x $agent
./$agent -server $server -group blue -v -name Morgan

Chaque agent supplémentaire (Sam côté rouge, Jordan côté bleu) se déploie en répétant l'opération dans un autre terminal avec un -name différent.

Scénario d'attaque retenu

CALDERA propose des profils d'adversaires prédéfinis. J'ai choisi un profil qui couvre plusieurs phases de la chaîne d'attaque pour une démonstration complète.

ProfilComportement simuléAdapté pour
DiscoveryReconnaissance du système (fichiers, utilisateurs, réseau)Démo simple, faible risque
CollectionCollecte de données sensibles sur la machine cibleDémo intermédiaire
ThiefVol de fichiers et d’identifiantsScénario clair à expliquer
Advanced ThiefVol puis exfiltration via Dropbox, FTP ou GitHubRetenu : couvre plusieurs phases ATT&CK
Defense EvasionTechniques pour échapper à la détectionTester la détection de la Blue Team
StowawayPersistance et mouvement sur le systèmeTester la phase de persistance

Le profil Advanced Thief simule le vol et l'exfiltration de données, ce qui touche plusieurs tactiques MITRE ATT&CK (collecte, exfiltration via un service externe). Son scénario est facile à raconter et tient dans une présentation de 5 minutes.

Exécution de la simulation

Côté Red Team

  1. Vérifier les agents : Alex et Sam doivent apparaître avec un indicateur vert (actif) dans Agents.
  2. Créer l'opération : Operations → +, nom Attaque-AdvancedThief, groupe red, adversaire Advanced Thief, planner atomic.
  3. Lancer avec Start : les techniques s'enchaînent automatiquement, avec un statut succès ou échec par étape.

Côté Blue Team

  1. Créer l'opération défensive : nom Defense-Blue, groupe blue, planner atomic.
  2. Lancer en parallèle ou après l'opération rouge pour observer la réaction défensive.
  3. Consulter le rapport avec View Report pour lister les actions exécutées côté défense.

Limite constatée

Le plugin gameboard, qui affiche normalement un tableau de bord Red vs Blue en temps réel, a besoin de Docker, indisponible dans cet environnement. J'ai donc comparé les deux équipes à la main, en confrontant le rapport de l'opération rouge à celui de l'opération bleue.

Méthode d'analyse

La comparaison se fait phase par phase du cycle ATT&CK (reconnaissance, accès initial, persistance, mouvement latéral, exfiltration) :

  • une technique réussie côté rouge = +1 point pour l'équipe rouge ;
  • une détection ou un blocage constaté côté bleu (logs, EDR, audit) = +1 point pour l'équipe bleue.

La méthode est manuelle, mais traçable : elle s'appuie sur les rapports d'opération de CALDERA, exportables en JSON via l'API.

curl -s -u admin:admin http://localhost:8888/api/v2/operations/<ID>/report > rapport.json

Conclusion et axes d'amélioration

Le déploiement de CALDERA sur trois VM Debian a permis de mettre en place une simulation Red vs Blue fonctionnelle, malgré plusieurs obstacles à l'installation (version de Go, build de l'interface, conflit de port, environnement virtuel Python). Chacun a été résolu méthodiquement et documenté. Le projet m'a donné une mise en pratique concrète du Purple Teaming et du référentiel MITRE ATT&CK dans un cadre maîtrisé et reproductible.

Pistes d'amélioration

  • Activer Docker pour débloquer gameboard (score en temps réel) et builder (agents personnalisés).
  • Finir le diagnostic du plugin response pour obtenir une réponse défensive automatisée au lieu d'une comparaison a posteriori.
  • Tester un second profil (par exemple Defense Evasion) pour évaluer la capacité de détection de la Blue Team.
  • Ajouter un démarrage automatique (systemd ou screen) pour éviter les conflits de port dus à des instances orphelines.
