Kubernetes avec Minikube

Mon premier cluster Kubernetes local : de l'installation des outils au démarrage de Minikube.

KubernetesMinikubekubectlUbuntu 24.04
ObjectifInstallationDémarrageCommandesBilan

Objectif

Installer un cluster Kubernetes local avec Minikube et manipuler les commandes kubectl de base pour déployer, exposer, mettre à l'échelle et mettre à jour une application.

Minikube v1.38.1kubectl v1.35.5Kubernetes v1.35.1Ubuntu 24.04driver Docker

Installation

Première commande, premier obstacle : kubectl n'est pas installé. Je l'ai installé avec snap, puis j'ai constaté que minikube manquait aussi (le paquet Debian suggéré par le système, minitube, n'a rien à voir). J'ai donc téléchargé le binaire officiel de Minikube et l'ai installé dans /usr/local/bin.

sudo snap install kubectl --classic
kubectl version --client

curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
sudo install minikube-linux-amd64 /usr/local/bin/minikube
rm minikube-linux-amd64

Démarrage du cluster

minikube start a sélectionné automatiquement le driver Docker, téléchargé l'image de base et les composants Kubernetes, puis créé un conteneur de 2 CPU et 3 Go de mémoire qui héberge le cluster.

Commandes étudiées

Voici les commandes de base que j'ai travaillées, dans l'ordre d'un déploiement :

CommandeCe qu’elle fait
minikube startDémarre le cluster Kubernetes local
kubectl cluster-infoAffiche les adresses du plan de contrôle pour confirmer que le cluster est joignable
kubectl create deployment mon-app-web --image=nginx:1.23Demande au cluster de télécharger une image et de la lancer dans un pod
kubectl expose deploymentCrée un service réseau pour ouvrir un port et rendre l’application accessible
kubectl port-forwardCrée un tunnel temporaire entre un port de ma machine et celui de l’application
kubectl get podsListe les pods et leur statut en temps réel (création, prêt, erreur)
kubectl scale deploymentChange le nombre de répliques de l’application pour s’adapter à la charge
kubectl set imageDéclenche une mise à jour en remplaçant l’image par une nouvelle version
kubectl rollout statusSuit le déroulement de la mise à jour des pods
kubectl execOuvre un terminal dans un pod
kubectl logsAffiche les messages et erreurs de l’application pour déboguer
kubectl deleteSupprime proprement une ressource (déploiement, service...)
# Exemple de déploiement d'un serveur Nginx
kubectl create deployment mon-app-web --image=nginx:1.23
kubectl expose deployment mon-app-web --type=NodePort --port=80
kubectl get pods
kubectl scale deployment mon-app-web --replicas=3

Cet exemple illustre l'enchaînement des commandes ; les captures ci-dessus montrent l'installation et le démarrage du cluster.

Ce que j'en retiens

  • Un cluster local complet démarre avec une seule commande (minikube start), sur le driver Docker.
  • Kubernetes s'utilise de façon déclarative : on décrit l'état voulu (image, nombre de répliques), le cluster fait le nécessaire pour l'atteindre.
  • Mise à l'échelle et mise à jour d'une application se font à la volée, sans arrêter le service.
