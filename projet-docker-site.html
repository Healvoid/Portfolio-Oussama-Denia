Héberger un site dans un conteneur Nginx

De la page HTML au conteneur : j'ai construit ma propre image Docker et je l'ai servie en local.

DockerDockerfileNginxWSL 2
ObjectifServeur NginxPage webDockerfileRésultatDiagnosticNettoyageBilan

Objectif

Mettre en pratique ce qui précède sur un cas concret : lancer un serveur web Nginx dans un conteneur, puis construire ma propre image contenant une page personnalisée, et la servir sur un port de ma machine.

Docker 29.5.2Ubuntu (WSL 2)nginx:alpine

1. Premier serveur Nginx

La première tentative échoue : « The command 'docker' could not be found in this WSL 2 distro ». Docker n'était pas encore accessible depuis la distribution WSL 2, il faut activer l'intégration WSL dans Docker Desktop. Une fois fait, docker --version confirme l'installation et le conteneur démarre.

docker --version
docker run -d -p 8080:80 --name mon-premier-serveur nginx
docker ps

L'option -p 8080:80 relie le port 8080 de ma machine au port 80 du conteneur, où écoute Nginx.

2. Créer la page web

Dans un nouveau dossier mon-projet-docker, j'ai créé un fichier index.html. Premier piège : avec des guillemets doubles, le ! déclenche l'expansion d'historique de bash (event not found). Avec des guillemets simples, le fichier est bien créé.

mkdir mon-projet-docker
cd mon-projet-docker
echo '<h1>Bonjour, ceci est mon super site dans Docker !</h1>' > index.html

3. Dockerfile et construction de l'image

Le Dockerfile tient en deux lignes : partir de l'image légère nginx:alpine et copier ma page dans le dossier servi par Nginx.

FROM nginx:alpine
COPY index.html /usr/share/nginx/html/
docker build -t mon-site-perso .
docker run -d -p 8081:80 --name conteneur-site-perso mon-site-perso

4. Résultat dans le navigateur

5. Observer et diagnostiquer

docker logs affiche ce qu'a écrit Nginx au démarrage (version 1.31.1, plusieurs processus worker). docker exec -it ouvre un terminal dans le conteneur pour vérifier que ma page est bien là.

6. Arrêt et nettoyage

docker ps -a
docker stop mon-premier-serveur conteneur-site-perso
docker rm mon-premier-serveur conteneur-site-perso
docker rmi mon-site-perso

Ce que j'en retiens

  • Un Dockerfile décrit une image de façon reproductible ; l'image sert ensuite à créer autant de conteneurs que nécessaire.
  • Le mappage de ports (-p hôte:conteneur) est ce qui rend un conteneur joignable depuis le navigateur.
  • logs et exec sont les deux outils de base pour comprendre ce qui se passe dans un conteneur.
  • Il faut arrêter (stop) puis supprimer (rm) les conteneurs, et supprimer les images à part (rmi).
